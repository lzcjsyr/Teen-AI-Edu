# HTML 课程页面自由构图参考

本文件只在需要生成或大幅重写 HTML 课件时作为轻量参考。它不是模板库，不要求固定类名、固定版式或固定页面槽位。

目标：让 AI 根据课程内容和审美判断自由设计，同时保留课程网页最基本的可读性、统一性和可检查性。

## 先做设计判断

写 HTML 前，先快速判断三件事，不需要在最终页面展示：

1. 这套课程应该是什么气质：训练手册、产品工作台、编辑长图、白板推演、课堂讲义，或其他更合适的方向。
2. 每页最重要的信息关系是什么：流程、层级、对照、表格、提示词、案例、章节过渡、总结行动等。
3. 每页最应该避免什么：普通文章化、卡片堆叠、标题压过内容、提示词截断、表格挤压、流程看不出动作。

## 自由构图原则

- 不要把这里的词变成固定模板。可以组合、变形、重写。
- 课程整体要像同一个产品：字体、页码、导航、间距和色彩系统统一。
- 每页构图要服务内容关系，而不是为了“看起来不同”随意变化。
- 卡片只是工具，不是默认答案；流程、层级、表格、代码区、工作台界面、信息图都可以用。
- 页面标题、画面内容、底部结论和设计提醒各司其职，不要把 Markdown 原文整段搬进网页。
- 视觉审美可以自由发挥，但中文必须清楚可读，桌面和移动端不能重叠、截断或横向溢出。

## 最低保真要求

- 提示词、代码、命令：必须完整保留，可复制，不被按钮遮挡。
- 表格：保持表头、列关系和可读性；移动端可横向滚动。
- 流程：每一步有动作动词，顺序清楚。
- 层级：能看出上下、先后或包含关系，不要误做成无差别并列。
- 章节分割：信息少、过渡感强，不提前塞满解释。
- 总结页：给出明确收束或下一步，不只写感谢语。

## 反模式

- 所有页面都是“标题 + 三/四张卡片”。
- 为了遵守所谓模板而牺牲审美和内容理解。
- 页面之间视觉完全漂移，看不出是同一门课。
- 用小字号硬塞内容，或让标题大到压迫主体。
- 把 `定位`、`设计提醒`、`讲者备注` 当成可见正文。
- 为了好看改写、截断或隐藏关键提示词和表格内容。
