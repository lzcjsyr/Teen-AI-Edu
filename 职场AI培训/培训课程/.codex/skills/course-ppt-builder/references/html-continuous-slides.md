# HTML 连续滚动分页课程页面生成参考

当用户选择“HTML / 网页版课件 / 打开一个 HTML 文件 / 连续滚动网页讲义”时读取本文件。实际生成或大幅重写 HTML 时，可读取 `html-page-templates.md` 作为轻量构图参考；不要套固定模板。

核心目标：生成一份 web-native 的连续滚动课程页面。它不是 Markdown 转码，也不是默认 16:9 仿 PPT；但每个 Markdown 课程页仍必须对应一个完整页面区块，有统一页码、清楚分割和稳定阅读顺序。

## 产物路径

默认结构：

```text
第一课/
├── 课程稿.md
└── 课件成品/
    ├── 课程网页.html
    └── 资源/
        ├── 图片/
        └── 字体/
```

- 课程 Markdown 保留在课程文件夹根目录，例如 `第一课/课程稿.md`。
- HTML 和展示资源放在 `第一课/课件成品/` 内。
- 文件夹和资源子目录必须使用中文命名，不要使用 `generated_html/`、`assets/`、`images/` 等英文目录名。
- HTML 默认做成可直接打开的本地文件；可使用少量 JS 做右侧页码导航、复制提示词、进度条或回到顶部。

## 分页结构

- Markdown 中的 `#### 【第 N 页：页面标题】` 必须 1:1 对应 HTML 中一个 `.course-page`。
- `.course-page` 必须横向独占完整可用宽度，不能把两个课程页并排，也不能把相邻页塞进同一个卡片、网格或模块。
- 页码从 1 到总页数连续出现，格式和位置整套课程统一，例如 `第 06 页 / 共 23 页`。
- 每页根据内容自然增高；页面之间必须有明显分割线、背景带、间距或页面编号栏。
- 章节分割页也是完整页面区块，不要降级成普通小标题。
- 默认不固定 16:9。只有用户明确要求“16:9 / 一页一屏 / 键盘翻页 / 打印成页”时，才使用固定画布。

推荐骨架。实际页面可以自由调整内层结构，但必须保留 `.course-page`、统一页码、页面锚点和清楚的内容层级：

```html
<nav class="page-nav" aria-label="课程页导航">
  <a href="#page-01" class="active">01</a>
  <a href="#page-02">02</a>
</nav>
<main class="course">
  <section class="course-page page-[purpose]" id="page-01" data-page="1">
    <div class="page-inner">
      <header class="page-header">
        <span class="page-number">第 01 页 / 共 23 页</span>
        <span class="page-section">章节名</span>
      </header>
      <div class="page-title-block">
        <p class="eyebrow">页面类型</p>
        <h1>页面主标题</h1>
        <p class="subtitle">可选副标题</p>
      </div>
      <div class="page-body">...</div>
      <footer class="page-conclusion">...</footer>
    </div>
  </section>
</main>
```

骨架规则：页码、页面内边距、最大阅读宽度、字体和色彩变量整套课程统一；每页只允许一个主标题 `h1`；`page-conclusion` 有内容时作为页面收束，没有内容可省略。

## 右侧页码导航

HTML 课程页必须提供右侧页码导航，用来显示当前位置并点击跳转到对应页面。按 `frontend-design` 的 HTML page-based experience 思路处理：这是服务阅读和课堂展示的前端信息架构，不是装饰组件。

- 桌面端导航固定在右侧可视区域，显示连续页码或短标题，不遮挡正文；当前页必须有明显 active 状态。
- 导航链接指向每个 `.course-page` 的锚点，例如 `#page-01`；点击后平滑滚动到对应页面。
- 用 `IntersectionObserver` 或等效轻量 JS 根据滚动位置更新 active 状态；不要依赖手动维护。
- 移动端改为顶部或底部紧凑导航，可横向滚动或折叠，不要挤压页面正文。
- 导航是辅助定位工具，不替代页面内统一页码；每个页面仍要显示 `第 06 页 / 共 23 页` 这类页码。

## 内容转换

生成 HTML 前，先确定整套课程的视觉方向，再快速判断每页的课堂功能、信息关系和需要避免的反模式。页面主标题来自 `#### 【第 N 页：页面标题】` 中的标题部分；页面内容来自 `页面设计` 中的 `页面类型`、`主视觉`、`画面内容`、`底部结论` 和 `设计提醒`。

转换原则：

- 课程页标题是页面主标题，不显示解析用的 `第 N 页`。
- `定位`、`设计提醒`、`讲者备注` 是给生成器或讲课人看的，不要作为可见正文。
- `画面内容` 要拆成适合网页阅读的组件，不要整段粘贴 Markdown。
- `底部结论` 用作页面收束，不混进正文段落。
- 如果 Markdown 没写清 `页面类型` 或 `主视觉`，从标题和内容推断信息关系和构图，不要退回普通文章布局。
- 内容多时用合适结构或自然增高，不要缩小字号硬塞。

## 视觉原则

- 审美可以自由发挥，但要像同一个课程产品：字体、色彩、页码、导航和间距系统统一。
- 页面结构服务内容理解，不要所有页都变成“标题 + 三/四张卡片”。
- 中文必须清楚可读；桌面和移动端都不能重叠、截断、贴边或横向溢出。
- 关键概念、关键词和结论差异要有明确高亮，但不要把整段文字都做成强调。
- 提示词、代码、表格和数字步骤要优先保证完整、可读、可复制、可检查。

## 交互边界

默认只做服务阅读和课堂展示的轻量交互：

- 右侧页码导航、锚点跳转和当前页高亮
- 复制提示词按钮
- 阅读进度条或回到顶部按钮
- 可选打印样式

不要增加复杂动效、游戏式互动或需要服务器支持的功能，除非用户明确要求。

## 交付前检查

必须用浏览器、Chrome headless、Playwright 或可用截图工具做视觉抽查。至少检查：

- 封面页
- 课程地图页或章节分割页
- 一个带数字徽章、步骤编号或流程圆点的页面
- 一个提示词页
- 一个表格、对比或信息密度高的页面
- 一个移动端代表页面

检查项：

- HTML 文件可直接打开。
- Markdown 每个课程页都 1:1 对应 `.course-page`，顺序无错乱。
- 页面连续滚动，默认不固定 16:9。
- 每页横向独占完整宽度，没有两页并排。
- 页码位置和格式统一，页面分割明显。
- 右侧页码导航可点击跳转，并能随滚动高亮当前页；移动端不遮挡正文。
- 页面构图匹配 Markdown 的页面类型、主视觉和画面内容。
- 主标题、内容组件、底部结论和设计提醒被正确处理。
- 数字徽章视觉居中，顺序/层级使用阿拉伯数字。
- 关键词高亮能帮助读者抓重点，且数量克制、样式统一。
- 文本与真实背景对比清楚。
- 桌面和移动端无重叠、截断、横向溢出。
- 提示词完整可读，复制按钮不遮挡正文。
- 页面风格统一，能看出明确视觉方向；不同页面按内容关系有节奏变化，不是机械套固定模板。

高频问题重点关注：

- 右侧页码导航是否压住正文、表格、提示词复制按钮或底部结论；移动端底部/顶部导航是否挡住最后一行内容。
- 页面锚点跳转后是否停在正确页面；当前页 active 状态是否滞后、跳错或卡在上一页。
- 长标题、长中文词、英文文件名、模型名、价格表头、路径名是否换行异常、挤出容器或造成横向滚动。
- 提示词和代码块是否被截断、字号过小、行距过密、按钮遮住文本，或复制按钮在 `file://` 本地打开时失效。
- 表格是否在桌面端列宽失衡、数字列不对齐；移动端是否能横向滚动且不把整页撑宽。
- 流程页的数字徽章、步骤圆点、箭头、时间轴节点是否视觉居中，是否因卡片等高导致大面积空洞或文字贴边。
- 嵌套布局是否因 `min-height`、`1fr` 或 grid/flex `stretch` 把流程卡、步骤卡、对比卡拉得过高，造成下半部分大面积空白。
- 页面内固定高度、`min-height`、网格列数是否让内容密集页被压扁；自然增高后页面间分割是否仍然清楚。
- 封面、章节分割页和金句页是否加入了多余说明文字，导致原本应强聚焦的页面变得像普通目录页。
- `定位`、`设计提醒`、`讲者备注` 是否被误放进可见正文。
- 页面数量、页码文字、右侧导航数量、`.course-page` 数量是否一致；最后一页是否显示正确总页数。
- 背景纹理、浅色文字、强调色和表格底色是否导致对比不足，尤其是投影、半透明层和深色章节页。
- 截图是否只检查了第一页；必须覆盖封面、章节/地图、流程、提示词、表格/高密度内容和移动端。

发现明显问题时，先修改 HTML/CSS，再重新截图或复查至少一次。不能只做静态代码检查；如果当前环境无法截图，最终回复中说明原因，并至少做 DOM/尺寸检查作为降级。

最终回复写清楚：Markdown 文件路径、HTML 文件路径、总页数、打开方式、截图抽查页面和自我修复情况。
