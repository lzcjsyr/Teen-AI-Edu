# 操作前检查与验收

## 必做前置

本案例源文件为 `.xls`，读取前请确认 `xlrd` 已安装；同时确认 `openpyxl` 可用于输出 `.xlsx`。可以在本文件夹根目录执行：

```bash
python3 -m pip install -r skills/delivery-xlsx/requirements.txt
```

如果 AI 助手不能安装依赖或读取本地文件，应先解决运行环境，不要把包含业务数据的文件上传到不受控的外部服务。

## 使用方式

先让 AI 读取实际文件的工作表、表头和前几行样本，再由 AI 确认商品名称列、金额列和有效数据区。不要把本样例的行号、列号或文件名当成通用规则；换成其他明细表时，应重新识别结构。

分类标准以 `skills/delivery-xlsx/references/classification_rules.md` 为准，7 个科目代码和科目名称不能新增、合并或改名。

## 本样例的验收事实

- 分类结果应为 1173 行 × 12 列；1170 条有品名的明细均有科目代码和科目名称。
- 按科目代码/科目名称汇总全部 7 类（含包装类、低值易耗），总金额应为 44,218.51，与原始明细一致；占比合计约 100%。
- 同目录的“参考成果/饭堂4月进货明细_已分类.xlsx”是本样例的标注基线；重新运行时，相同商品的分类和 7 类金额汇总应与它一致，发现差异要先复核分类映射。
- Skill 的回写承诺是数据结构和单元格值，不保证保留原 `.xls` 的全部格式、合并单元格、公式、多工作表或打印设置。
- 每个有品名的明细都应归入既有 7 类之一。模糊商品仍选择最接近的科目，并在 HTML 报告中列出人工复核清单；不要创建“待人工确认”科目。

## HTML 报告验收

- 报告文件由实际输入文件名动态生成，并与分类明细、分类汇总放在同一交付目录。
- 双击 HTML 即可打开；图表、中文、金额和百分比不依赖联网。
- 报告中的总金额、分类金额和占比应与汇总表一致。
- 如果使用外部字体或图表库，必须改为项目内资源，或明确说明联网要求；推荐使用内嵌 CSS、SVG 和 JavaScript。
