# 02 确认主题、选择模式和核验来源

目标：用户确认主题后，判断本次属于哪种整理模式，核验数据源，并为生成内容母版准备证据底座。

## 进入条件

- 用户确认了第 1 步中的某个候选选题；或
- 用户一开始就给了明确选题/来源。

人工确认后直接推进，不再由 AI 判断“是否值得做”。

## 选择模式

先判断本次属于哪种模式，并在后续 `master_content.md` 中写明：

### 模式 A：单一内容解读

用于梳理某个明确内容，例如：

- OpenAI 或 Anthropic 的某篇报告
- 某家公司博客、技术报告、产品发布
- 某篇论文、政策文件、演讲或访谈

来源规则：

- 默认限制为 1 个主数据源。
- 可以补 1 到 2 个背景来源，只用于解释上下文或术语。
- 不要把多个媒体评论混进正文，避免变成话题综述。
- 母版重点是“这份内容说了什么、没说什么、对企业意味着什么”。

### 模式 B：话题观点梳理

用于梳理某个议题，例如：

- “企业 Agent 治理现在主流怎么看”
- “AI 搜索的商业模式有什么变化”
- “模型价格下降对企业软件意味着什么”

来源规则：

- 可以引用多个来源。
- 优先一手来源、研究机构、权威媒体、知名专家或高质量 newsletter。
- 目标是整理主流观点、共识、分歧和企业影响。
- 社交讨论只能补充关注点，不能当作事实依据。

## 创建内容母版目录

用脚本创建目录、内容母版文件和 `sources/` 子目录：

```bash
python skills/youchuang-ai-media/scripts/create_master_folder.py "<短标题>"
```

## 通用数据源优先级

AIHOT 是发现来源，不是最终核验来源。确认主题后，按模式补充：

1. 一手来源：公司博客、官方产品页、技术报告、价格页、政策文件、政府发布、标准组织、会议页面。
2. 高权威二手来源：可信商业/科技媒体、分析机构、研究机构、大学实验室、知名 newsletter。
3. 社交讨论来源：X、LinkedIn、小红书、知乎、即刻、B站、抖音、微信文章。只用于理解关注点和反对意见，不单独证明事实。
4. 内部来源：优创Hub培训笔记、客户问题、流程模板、Skills、Gitee资料、过往案例。

## 主要来源留存

若报告、论文、官方 PDF、公司博客、技术公告或政策文件是母版的主要参考依据，尽量把原文保存到母版目录的 `sources/` 子目录。

- PDF/报告/论文：优先保存原始 PDF。
- 网页文章：优先保存可复查的 HTML、Markdown 或浏览器导出的 PDF。
- 文件命名：`YYYY-MM-DD_发布方_短标题.ext`，无法确定日期时用访问日期。
- 在母版“证据底座”里同时写原始 URL 和本地文件路径。
- 不必保存普通新闻转载、社交帖、搜索结果页、无法稳定访问或版权/登录限制明显的页面；这类只记录 URL 和用途。

## 生成母版前的核验要点

不要单独生成素材整理文件。生成 `master_content.md` 前，先在工作过程中确认以下素材，并把必要内容直接写入母版的“证据底座”等对应栏目。

应包含：

- 用户确认的选题
- 本次模式：单一内容解读 / 话题观点梳理
- 如来自第 1 步候选，明确最终推进的是哪个选题；不用保存完整候选列表
- AIHOT 原始条目和发布时间，如适用
- 主数据源；如为模式 B，再列出多个权威来源
- 背景补充来源，若有
- 来源标题、发布方、发布日期、URL
- 主要参考源的本地留存路径，如已保存
- 每个来源支撑的具体事实
- 模式 B 需额外记录：主流观点、共识、分歧、代表性引用方向
- 已确认事实
- 合理推断
- 未知或待核验信息
- 可用于母版的关键素材、数字、案例、原句摘要
- 可支撑的企业影响方向
- 不适合对外写成结论的内容

## 写法

可以继续制作存在不确定性的选题，但必须把不确定性写清楚。不要把传闻、泄露、社交帖子或单一媒体报道写成强事实。
